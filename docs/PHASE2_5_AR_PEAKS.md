# PHASE 2.5 — AR 산봉우리 방향 후보

기반: `feature/phase2-gps-ar-ready` (`bf646dc`). 작업: `feature/phase2-5-ar-peaks`.

## 저장소 분석과 범위

기존 Expo Router `app/peak-finder.tsx`는 CameraView, 위치 권한, 단발 GPS와 진북 나침반을 갖추고 있었다.
`src/ar/peaks.ts`에는 거리·방위각·가로 위치 계산이 있었으나 봉우리 목록은 비어 있었다.
도감/산 앨범은 `/mountain/[id]`, 기본 산 ID는 `src/data/sample.ts`에 있고 산행·뱃지는
JournalContext → SQLite → `core/engine.ts` 경로로 처리한다.

이번 구현은 Expo SDK 57 + Expo Go에서 가능한 **전경 카메라·GPS·진북·가속도 기반 방향 후보**다.
카메라 영상 인식, ARKit, 정상 도착 인증, 배경 GPS, 사진 저장, 지도 안내는 이번 변경에 포함하지 않는다.
산행·앨범·도감·뱃지의 기존 저장 및 판정 코드는 수정하지 않았다.

## 구현

- 카메라 위 최대 3개 이름표: 산/봉우리 이름, 원본 해발고도(m), 현재 GPS에서의 직선거리(km).
- 화면 중심 방향에 가까운 후보 우선, 동률은 거리순. 방향순으로 서로 다른 행에 배치하며
  가까운 방향의 봉우리도 터치 영역이 겹치지 않도록 한다. 후보가 1개면 1개만 표시한다.
- 이름표를 누르면 기존 mountainId로 산 도감/앨범을 연다. 이 동작은 방문 기록이나 보상을 만들지 않는다.
- GPS 정확도 50m 이하, 진북 유효·나침반 등급 2 이상일 때만 후보를 표시한다.
  Expo iOS 등급 2는 불확실성 <35°, 등급 3도 <20° 수준이므로 실제 봉우리 일치를 보장하지 않는다.
- GPS 20초, 방향 10초, 기울기 3초보다 오래된 값은 숨긴다. 미래 시각·NaN·잘못된 좌표도 거부한다.
- 가속도에서 중력 방향을 근사한다. 기기를 앞뒤로 20° 넘게 기울이거나 옆으로 15° 넘게 기울이면
  후보를 숨기고 보정 안내를 표시한다. 움직임/진동 중에도 숨긴다. 이 방식은 정밀 자세 추정이 아니다.
- 화면 이동·백그라운드·잠금 시 카메라를 분리하고 이 화면의 센서 구독을 해제한다.
  비동기 권한/구독 완료가 늦게 도착해도 구독을 제거한다. 돌아오면 새 측정을 시작한다.
- 권한 거부·서비스 중단·카메라 오류 안내 및 수동 재시도. 영구 카메라 권한 거부 시 설정으로 이동한다.
- 사진/사용자 좌표/나침반 측정은 AR 기능에서 저장하거나 전송하지 않는다.
  출처 버튼을 사용자가 누르면 공개 출처 페이지가 열리지만 위치를 URL에 붙이지 않는다.

## 데이터와 검증의 의미

2026-10-22에 OpenStreetMap 공식 API에서 `natural=peak` 노드를 확인한 공개 데이터 3개를 내장했다.
산의 중심점·개인 GPS 기록으로 정상 좌표를 대신하지 않았다. 표시 고도는 OSM 원본의 `ele`(미터)를
그대로 옮긴 값이다. `verified`는 **고정 버전 공개 원본과 좌표·고도를 대조했다**는 뜻이며,
측량 정확성, 국립공원/산림청 인증, 현장 검증이나 공식 표고와의 일치를 뜻하지 않는다.
OSM은 기여자 편집 데이터로 오류가 있을 수 있다. 공식 자료의 높이와 다를 수 있으므로
고정밀/안전 용도로 쓰기 전에 공식 측량 자료와 교차 검증이 필요하다.

| 표시 이름 | 위도 WGS84 | 경도 WGS84 | 원본 고도 m | 고정 원본 |
| --- | --- | --- | --- | --- |
| 북한산 · 백운대 | 37.6586301 | 126.9780032 | 835.57 | [노드 5515194671 v5](https://api.openstreetmap.org/api/0.6/node/5515194671/5) |
| 도봉산 · 자운봉 | 37.6988424 | 127.0154594 | 740.2 | [노드 5515194666 v6](https://api.openstreetmap.org/api/0.6/node/5515194666/6) |
| 관악산 | 37.4451398 | 126.9642379 | 632 | [노드 442878166 v14](https://api.openstreetmap.org/api/0.6/node/442878166/14) |

`src/data/peak-catalog.json`은 버전 1의 데이터와 출처 버전·원본 이름·확인일·선택 필드 SHA-256을 보관한다.
원본의 편집자 이름/사용자 ID는 보관하지 않는다. `src/data/peaks.ts`가 앱용 모델로 변환하므로 계산과
센서는 데이터 제공 경로에 의존하지 않는다. 추후 다운로드/로컬 캐시도 같은 모델을 공급할 수 있다.
현재 내장 JSON은 인터넷 없이 읽지만, 추가 데이터 다운로드·갱신·사용자 오프라인 저장 UI는 미구현이다.
좌표와 표고 데이터의 라이선스는 [ODbL 1.0](../src/data/PEAK_DATA_LICENSE.md)이다.

원본 재검증(인터넷 및 Python 3 필요, 저장소 파일을 변경하지 않음):

```sh
python3 scripts/verify_peak_sources.py
```

세 노드의 정확한 버전을 HTTPS로 다시 읽어 좌표, 이름, `natural`, `ele`, 버전, 시각과 정규화된
선택 필드 SHA-256을 비교한다. 미터·WGS84를 유지하고, 데이터 추가 시 산 ID 연결과 출처를 검토해야 한다.
이 스크립트는 공개 원본 대조이며 독립 측량 검증은 아니다.

## 화각·기울기·가림의 한계

- 가로 투영은 `0.5 + tan(방향차) / (2 × tan(추정 수평 화각/2))`를 사용한다.
  기본 화각 45°, 선택 35°/55°는 근사값이다. Expo CameraView는 이 구현에 필요한
  실시간 카메라 내참수/유효 수평 화각을 제공하지 않으며 렌즈·미리보기 잘림에 따라 오차가 난다.
  후면 기본 광각 렌즈와 디지털 줌 0(1×)을 요청한다. 실제 렌즈 선택은 실기기 확인이 필요하다.
- 이름표 높이는 가독성을 위한 고정 행이다. 사용자 고도·카메라 피치·수직 화각·DEM을 결합한
  정상의 세로 투영은 하지 않는다. 정상 픽셀에 이름표가 붙었다고 해석하면 안 된다.
- DEM이나 건물 모델이 없어 지형 가림을 판정하지 않는다. 가려진 봉우리도 후보에 나올 수 있다.
- 등록된 봉우리는 서울·경기 3개뿐이고 범위는 50m 이상~45km 이하이다.
  후보 없음은 주변에 산이 없다는 뜻이 아니다. 곡률·굴절·시계·날씨를 모델링하지 않았다.
- ARKit 자세 추적/카메라 보정·DEM 가시성·실제 영상 식별은 별도 개발 단계다.
  Expo Go에서 이번 시제품을 시험한 뒤 네이티브 개발 빌드가 필요한 기능을 따로 계획한다.

## 검증 기록

클라우드 Linux / Node 24.19.0 / npm 11.9.0에서 수행. 아래는 실제 기기 테스트가 아니다.

- 기존 기반: TypeScript 통과, 단위 테스트 19/19 통과.
- 변경 후: TypeScript 통과, 단위 테스트 38/38 통과.
  방위각 경계·화각·거리·데이터 누락·품질/최신성·기울기·출처/도감 연결,
  센서 구독 해제·늦은 비동기 완료·권한 거부/재시도와 기존 GPS/뱃지 로직을 검사했다.
- 원본 재검증: 3/3 노드의 좌표·고도·버전·체크섬 대조 통과.
- Metro 전경 개발 서버: 실행·재시작 후 iOS SDK 57 매니페스트 HTTP 200 및 앱 이름/SDK/launch asset 확인 통과.
- iOS JavaScript/Hermes 번들: 통과. 네이티브 iOS 빌드나 iPhone 구동 검증을 뜻하지 않는다.
- Expo Doctor: 21개 중 19개 통과. 설정 스키마와 React Native Directory 온라인 검사는
  `exp.host`, `reactnative.directory` 접근 차단으로 실패하여 **미검증**이다.
  버전 호환·필수 peer·중복 네이티브 모듈 검사는 통과했다. 검사 무시 설정은 추가하지 않았다.
- `react-test-renderer`의 폐기 예정 경고가 발생하지만 센서 훅 테스트는 실행·통과한다.
  네이티브 카메라나 물리 센서의 정확도를 검증하지 않는다.

설치 중 최신 자동 peer 선택이 React 19.2.3과 충돌하는 React DOM과 SDK 외 worklets를 가져오는 문제를
확인했다. Expo SDK 57의 bundledNativeModules에 맞춰 react-dom 19.2.3,
react-native-reanimated 4.5.1, react-native-worklets 0.10.1을 고정하고 package-lock.json 및 CI의 npm ci를 추가했다.
expo-sensors도 SDK 57의 57.0.3을 사용한다. 패키지/TLS/체크섬 검증을 끄지 않았다.

재현 명령(프로젝트 루트):

```sh
npm ci
npm run typecheck
npm test
npx expo-doctor
npx expo export --platform ios --output-dir .expo-ios-export --max-workers 2
npx expo start
```

클라우드의 읽기 전용 홈에서는 `EXPO_NO_TELEMETRY=1 CI=1`을 Expo 명령에 붙였다.
Metro는 Expo CLI의 셸 전용 `__UNSAFE_EXPO_HOME_DIRECTORY=/workspace/.fathers-expo-state`와
`XDG_CACHE_HOME=/workspace/.fathers-cache`로 저장소 밖의 권한 700 로컬 상태/캐시 디렉터리를 사용했다.
이 설정은 프로젝트 .env에 넣거나 인증 값을 복사하지 않았다. `EXPO_NO_TYPESCRIPT_SETUP=1`로
CLI의 TypeScript 파일 자동 수정을 막고 `--offline --port 8081 --max-workers 2`로 로컬 검사했다.
데스크톱 React Native DevTools는 클라우드 Chromium SUID 샌드박스 제약으로 실행되지 않았으며
샌드박스를 비활성화하지 않았다. Metro 매니페스트 검사는 통과했지만 DevTools UI는 미검증이다.
프록시가 필요한 Node 24 환경의 온라인 검사에는 `NODE_USE_ENV_PROXY=1`도 사용했지만
호스트 정책에 의한 403 접근 차단은 해소하지 못했다. 사용자 PC의 일반 네트워크에서 Doctor를 다시 실행해야 한다.

## iPhone 13 mini / Expo Go 수동 확인표 — 모두 미검증

먼저 Expo Go의 SDK 57 지원을 확인한다. 기존 프로젝트에서 중복 clone/worktree를 만들지 말고:

```sh
git fetch origin
git switch feature/phase2-5-ar-peaks
npm ci
npx expo start --tunnel --clear
```

터널은 네트워크와 Expo CLI 터널 도구가 필요하다. 클라우드에서는 터널/계정 로그인을 시험하지 않았다.
로컬 네트워크에서는 `npx expo start --clear`로 확인할 수 있다.

1. 카메라·위치·정확한 위치·동작 권한 허용/거부, 영구 거부 후 설정 복귀, 재측정 버튼.
2. 실외에서 기기를 세로·수평으로 유지하고 GPS 오차와 진북 등급을 확인.
   서울·경기 등록 봉우리에서 45km 이내일 때 해당 방향에 후보가 뜨는지 확인.
   정상을 이미 알고 있는 안전한 관측 장소에서 예상 방향과 오차를 비교한다.
3. 북쪽 359°→0° 회전, 좌/우 화면 가장자리, 35°/45°/55° 화각 변경, 빠른 회전 시 점프/지연 확인.
4. 이름·해발고도·직선거리 읽기, 최대 3개 표시, 이름 탭으로 올바른 산 도감/앨범 연결.
5. 기울이기·가로로 돌리기·흔들기·자석 주변·실내 GPS 약화 시 표시 중단과 보정 안내 확인.
6. 화면 이동/복귀, 앱 백그라운드/잠금/복귀 후 카메라 중복 실행이나 오래된 후보가 남지 않는지 확인.
   장시간 정지 시 위치 watch 갱신 간격과 20초 만료 안내도 확인한다.
7. 375×812pt, 큰 글씨·VoiceOver에서 이름표 잘림/접근성·스크롤·터치 영역 확인.
8. GPS 산행 중 AR 화면 출입 후 기존 거리/일시정지/종료·산 지정·앨범·도감·뱃지 회귀 확인.
   AR 화면 열기/이름 누르기만으로 새 산행·뱃지가 생기면 안 된다.
9. 기내 모드에서 내장 목록은 유지되는지, 진북/GPS가 없을 때 후보가 숨겨지는지 확인.
   사진·위치가 새 파일이나 외부 서버로 저장/전송되지 않는지 확인한다.
10. 10~20분 전경 실행 중 배터리·발열·센서 안정성과 지형 가림 때문에 잘못 보이는 후보를 기록한다.
    테스트 결과에 위치·사진을 남길 경우 로컬 개인 폴더에 보관하고 GitHub에 올리지 않는다.

앱 배포, EAS 빌드/제출, Apple 개발자 가입·결제는 진행하지 않았다.
